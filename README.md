# ZCode 遥控

## 这是什么

「ZCode 遥控」是一个安卓 App，把 ZCode 桌面端自带的「移动端远程控制」手机页装进一个 WebView，让你用手机远程操作这台电脑上的 ZCode。配对、登录、消息中转全部由 ZCode 官方的手机页完成，App 本身不实现任何协议，只负责把页面装进来，并补上 WebView 默认缺少的原生能力（文件选择、返回键、保存副本等）。同一台电脑同一时间只允许一个手机页面在线，这是 ZCode 服务端的规则，App 也照此设计（全程只保持一个 WebView）。

## 安装

安装包（当前 0.3.0，versionCode 3，最低 Android 8.0 / API 26）在本仓库的 **[Releases](../../releases)** 页下载 `zcode-remote-release.apk`。同一来源目录下如果还有 `zcode-remote-debug.apk`，那是调试包，只能自己装着试，不要分发。

三种传到手机的方式，任选其一：

**① 数据线 + adb 安装**：

```bash
adb install -r zcode-remote-release.apk
```

路径里含中文等非 ASCII 字符时 adb 容易出问题，先复制到纯英文路径再装（`scripts/emulator-smoke.sh` 交给 adb 之前也是这样先复制一份）。覆盖升级要求新包的 versionCode 更大、签名是同一把钥匙——自己从源码构建的签名密钥和 Release 里的不同，切换来源时要先卸载再装。

**② 用 `scripts/serve-apk.sh` 起一个下载地址**：

```bash
bash scripts/serve-apk.sh
```

脚本会监听 8765 端口（用 `PORT=8766` 换端口、`BIND=<地址>` 限定监听地址），打印手机可用的下载地址：局域网地址（这一种需要手机和电脑连同一个网络），装了 Tailscale 的话会一并打印 Tailscale 地址（走 Tailscale 时不需要同一网络）。在手机浏览器打开打印出来的地址，下载 `zcode-remote-release.apk` 安装；打不开时先确认两台设备网络相通、电脑防火墙放行了该端口。这是个不带任何防护的静态文件服务，只在信得过的网络里临时用，**传完按 Ctrl-C 关掉**。

**③ 直接把文件发到手机**：U 盘、网盘、聊天工具传文件都行，拿到 `zcode-remote-release.apk` 后在手机上点开安装。

第一次装这种非应用商店的包，Android 会要求给来源应用（浏览器或文件管理器）授予「安装未知应用」的权限，按提示允许即可。

## 第一次使用

**先在电脑端做一次**：打开 ZCode 桌面端的「移动端远程控制」弹窗。打开一次远程控制就开启了，之后关掉弹窗不影响运行；哪些操作会把它停掉，见下面「电脑端要做的事」。弹窗里能看到二维码和「复制链接」。

**手机上要和电脑端用同一个登录平台、同一个账号**：手机页第一次打开会要求登录，界面上选「中国」或「全球」，必须和电脑端登录 ZCode 用的平台一致、账号相同，否则连不上自己的电脑。电脑端用的是哪个，以你当时登录桌面 ZCode 选择的为准；拿不准就先试一个——选错的表现要么是「选择电脑」列表里没有你的电脑（列表属于所选区域的账号），要么是提示设备不属于当前账号（主按钮是「切换账号」）。这时用 App「更多」→「退出登录」清掉登录态，重新登录时换另一个就行。

添加电脑的几种方式（第一次打开 App 是引导页，之后在「电脑」列表页随时可以再添加）：

| 方式 | 怎么做 |
| --- | --- |
| **免扫码入口** | 引导页上点「免扫码入口」。它打开 `https://zcode.z.ai/remote/v4?app_version=4.0.0`，登录同一账号后进入页面里的「选择电脑」列表，最近用过的电脑在线会自动连上。省掉的只是手机端扫码、复制链接这一步；电脑端仍要先开启远程控制（见上），否则那台电脑在列表里是离线的。 |
| **扫码** | 点列表顶部的「扫码」（引导页上是「扫码添加」），对准电脑端远控弹窗里的二维码。相机权限是进扫码页时才申请的；不授权也可以改用粘贴方式。 |
| **复制链接后粘贴** | 电脑端弹窗里点「复制链接」，回到手机 App 点「添加」（引导页上是「手动添加」），粘贴进输入框，或点「读取剪贴板」（读取前会先让你确认）。 |
| **系统分享或打开链接** | 在手机浏览器里打开链接后，用系统「分享」发给本 App；或直接在「打开方式」里选本 App。注意：`zcode.z.ai` 没有发布应用关联（assetlinks.json），系统不会自动唤起本 App——第一次要在「打开方式」里手动选一次，之后可以设为默认。 |

电脑端「复制链接」给出的地址形如：

```
https://zcode.z.ai/remote/v4?app_version=<桌面版本>&sid=<设备id>&mid=<机器码>&name=<电脑主机名>
```

App 会**原样保存、原样加载**这条链接，不拆开、不改写。链接等同于这台电脑的控制权，App 界面上平时只显示电脑名、不显示链接；想拿到链接本身，用「更多」菜单里的「复制当前链接」（你主动操作、带确认，见「日常使用」）。

## 日常使用

> 提示：下面与手机页有关的条目——按钮位置、附件上限、返回键去向、「保存副本」——依据 4.0.0 页面代码和模拟器上的测试页验证，还没有在真机的真实页面上逐一走过（详见「已知限制」）。页面改版后若有出入，以页面实际表现为准。

**返回键的三种去向**：

| 你在哪里按返回键 | 去哪里 |
| --- | --- |
| 手机页的聊天页 | 网页后退：回到手机页自己的首页（连着按，退到首页后再按就是下一行） |
| 手机页自己的首页、登录页、页面里的电脑列表等 | 回到 App 的「电脑」列表 |
| App 的「电脑」列表、添加页、扫码页 | 退回手机桌面（App 切到后台，不退出） |

**切换电脑**：回到 App 的「电脑」列表（页面首页按返回键即可），点另一台电脑就加载并连接它，列表上会用「使用中」标记当前这台。同一时间只有一台在线。列表每一项下面有「改名」和「删除」按钮——删除只是从手机列表里移除，电脑端的远程控制不受影响。

**发附件**：聊天输入区的附件按钮是手机页自带的（单条消息最多 8 个，上限来自页面代码），点下去弹出的是系统的文件选择器，支持多选。要传更多，最直接的办法是分多条消息发（没有专门验证过）；页面里反馈功能附截图的那个入口只收图片，弹出的是相册选择器。

**保存文件**：手机页里的「保存副本」按钮（单文件上限 50MB，同样是页面自己的限制），点后弹出系统的保存框，选好位置即写入；哪一步走不通会提示「暂不支持保存」或「保存副本失败」，不会卡住。超过 50MB 存不下来时，文件本来就在电脑上，直接在电脑端取。

**「更多」菜单**（「电脑」列表页顶部，和「扫码」「添加」并排）：

- **重新加载**：重载当前页面。
- **在浏览器中打开**：把当前页面交给系统浏览器。会先提示「同一台电脑同一时间只能一个页面在线」，因为浏览器里打开后 App 里的页面可能被踢下线（反过来也一样），请错开使用。
- **复制当前链接**：确认后才复制。链接等同于这台电脑的控制权，请像密码一样保管，不要发给不信任的人或群。
- **退出登录**：二次确认后清除 App 里保存的登录状态（等同网页里的「切换账号」），已添加的电脑不受影响，重新进页面时再登录一次即可。

## 电脑端要做的事

手机要随时连得上，电脑端只需要保证 ZCode 自身的运行条件（不需要装任何别的软件）：

- **ZCode 保持运行且已登录，窗口不能关。** 关掉那个桌面窗口会停掉这个窗口的远程控制。建议在电脑端 ZCode 的设置里打开**「关闭窗口时隐藏到托盘」**（设置项的确切位置工程文档里没有记录，按选项名找）。打开后点关闭按钮只是藏到托盘，托盘里的退出才会真正退出；最小化不影响。
- **不要点弹窗里的「停止」。** 点「停止」会停掉远程控制；退出登录也会停，重新登录同一账号会自动恢复。
- 建议同样在设置里打开**「保持电脑运行」**：它阻止系统因空闲进入休眠。注意它防不了合盖——要真正随时可连，就得不合盖、不断电、不断网。
- **重启电脑后要手动启动 ZCode**（桌面端没有开机自启功能）。启动后远程控制会自动恢复，不需要重新扫码。
- **网络要通。** 电脑端到中转服务器的连接走这台电脑的常规出网链路；如果它需要代理才能访问 `zcode.z.ai`，代理一停手机就连不上。
- 要在手机上访问的**工作区，得在开着远程控制的那个桌面窗口里打开**；一个桌面窗口只有一个远控会话，要换窗口就在那个窗口再点一次远控入口。

电脑休眠、断网或关窗口期间，手机端会在 15–30 秒内显示「桌面已断开」（这两个数来自工程文档对手机页超时参数的核对：等配对 30 秒、收到「电脑离线」后再等 15 秒，超时都算终态）；电脑恢复后自动重连，手机回到前台也会自动接上，不需要在电脑上补做任何操作。

## 常见问题

**被踢下线 / 会话冲突**
同一台电脑同一时间只允许一个手机页面，新开的页面会把旧的踢掉，两边互相抢会反复断连。常见触发：同一条链接又在浏览器、微信或另一台设备上打开了。处理：关掉别处的页面，只留一个。顺带：想长期用平板或别的手机的浏览器当客户端也可以（浏览器里打开免扫码入口并登录），但它和本 App 对同一台电脑互相排斥，选一个用，别两边同时开。

**提示「桌面已断开」**
多半是电脑休眠了、断网了、ZCode 退出了，或那个桌面窗口被关了。电脑恢复运行后手机会自动重连。如果页面根本没加载出来，App 会显示自己的错误页（「请确认电脑端 ZCode 正在运行且已登录」）和「重试」按钮——先去电脑上确认 ZCode 在运行且已登录，再点重试。

**登录过期**
登录凭证的有效期由服务端决定，手机网页不会自动续期。过期后页面自己回到登录页，并把当前链接留作重新登录后的返回地址——重新授权登录一次即可，电脑和链接都不用动。

**提示「旧版链接，请在电脑端重新打开远控弹窗扫码」**
你添加的链接带着 `hash` 或 `t` 参数，是旧版桌面端生成的，现在的手机页会直接拒绝。在电脑端重新打开「移动端远程控制」弹窗，用新的二维码或「复制链接」再添加一次。

**ZCode 升级后页面打不开**
链接里的 `app_version` 跟着桌面版本走，线上不一定为每个版本都保留手机页面（比如 4.0.1、4.1.0 的页面目录当时是 404）。App 的处理分两种：

- **保存的链接打不开（404）→ 自动改走免扫码入口。** 这是每次都会发生的：App 每回先试保存的链接，打不开就落到免扫码入口的「选择电脑」列表，从列表选中那台电脑即可连上，页面连上后自己按桌面真实版本工作，手机上已添加的电脑不用重新添加。想恢复「打开 App 直接连上」的体验，在电脑端重新「复制链接」，回 App 再添加一次——同一台电脑会自动归并成一条，保存的链接就更新成新的了（升级本身不改变链接里的设备标识，这是工程文档核对过的）。
- **免扫码入口也打不开 → 显示原生错误页。** 这说明 App 兜底入口指向的版本在线上失效了，要按「维护清单」换兜底版本常量、重新打包发版；在那之前免扫码入口用不了。

## 隐私与权限

- **申请的系统权限只有两个**：网络（WebView 联网）和相机（只在进扫码页时才申请）。另有一条 AndroidX 自动加入的应用内部签名级权限，不涉及任何系统资源。
- **链接存在哪**：电脑链接保存在 App 的私有存储（DataStore）里，只有本 App 能读；链接不写进日志（App 自己只记一条极简的加载日志，内容只有主机名和状态码），界面上只显示电脑名。
- **登录凭证存在哪**：只在 WebView 自己的 localStorage 里，App 代码不读取、不搬运、不打印。清除它只有一个入口——「更多」里的「退出登录」。
- **备份与迁移都关着**：清单里关闭了云备份，并用排除规则把设备到设备迁移也封掉。换手机、云备份都带不走链接和登录态，需要重新添加、重新登录。
- **为什么不做系统通知**：WebView 不支持网页通知 API，手机页自己也从不申请通知权限，而且页面一切到后台就挂起连接，本地通知没有意义；云端推送只面向官方 App，第三方接不进。需要任务提醒时，用电脑端自带的「使用 Bot Channel」（微信、飞书、Lark、Telegram）。
- **手机丢失怎么办**：立刻在电脑端远控弹窗里点「停止」——远程控制停下后，那台手机只会看到「桌面已断开」。但要清楚它的局限：「停止」**不会更换设备标识**（同一账号、同一端点下保持不变，重新开启后通常还是同一条链接），也**清不掉丢在手机上的登录态**——等你重新开启远程控制后，拿着手机的人只要登录态还有效，仍可能从免扫码入口连回来。所以丢了手机除了点「停止」，还要尽快处理账号本身（例如修改账号密码、在服务端退出会话）；账号侧的操作能不能让那台手机的登录失效，工程文档里没有记载，这里给不出确定步骤。

## 从源码构建与验收

前提：JDK 17 和 Android SDK（`platforms/android-37.1`、`build-tools/36.0.0`），位置记在 `scripts/toolchain.env`，换机器时改它；另外 Gradle 解析依赖用的代理写在用户级 `~/.gradle/gradle.properties`——它不属于本工程，换机器还要自行配置。还需要 `python3`。脚本都可以在任意目录下运行。

| 命令 | 做什么 | 通过标准 |
| --- | --- | --- |
| `bash scripts/check.sh` | 单元测试 + Android Lint（`testDebugUnitTest lintDebug`） | 退出码 0 |
| `bash scripts/build.sh debug` | 构建并复制为 `dist/zcode-remote-debug.apk` | 退出码 0 |
| `bash scripts/build.sh release` | 构建并复制为 `dist/zcode-remote-release.apk`（含 `lintVitalRelease`；没有签名密钥会先用 `make-keystore.sh` 生成） | 退出码 0 |
| `bash scripts/verify-apk.sh dist/zcode-remote-release.apk` | 安装包静态验收，逐项打印通过/不通过（包名、不可调试、不备份、权限白名单、无明文流量、导出组件、intent-filter、备份规则、已签名，共 9 项） | 退出码 0，9 项全过 |
| `bash scripts/serve-apk.sh` | 起下载地址传安装包（见「安装」） | 一直运行，Ctrl-C 停止 |
| `bash scripts/make-keystore.sh` | 生成 release 签名密钥（已存在则沿用） | 退出码 0 |
| `bash scripts/emulator-boot.sh` | 无界面启动安卓模拟器（AVD `zcode-remote-smoke`），等开机完成 | 退出码 0，打印 SERIAL/EMU_PID/BOOT_SECONDS |
| `bash scripts/emulator-kill.sh` | 关掉上面那个 AVD 的模拟器（对模拟器不是正常关机，没落盘的写入会丢） | 退出码 0 |
| `bash scripts/emulator-smoke.sh <apk路径>` | 交付前实跑：装上安装包、启动、用 VIEW 意图打开链接、查崩溃和 `pageLoaded` 日志、留截图，14 项逐项打印 | 退出码 0，14 项全过 |

**模拟器那三条用的 AVD `zcode-remote-smoke` 要先创建一次**（`emulator-boot.sh` 只负责启动，不建 AVD）。新机器上用 SDK 里的 avdmanager：

```bash
~/Android/Sdk/cmdline-tools/latest/bin/avdmanager create avd -n zcode-remote-smoke \
  -k "system-images;android-35;default;x86_64"
```

系统镜像（`system-images;android-35;default;x86_64`）需要先用 sdkmanager 装好。AVD 名和 SDK 位置可以用环境变量 `AVD_NAME`、`ANDROID_HOME` 覆盖。

**签名**：release 包用 `keystore/zcode-remote-release.p12` 签（口令在 `keystore.properties`，都不入库，权限 600）。这两个文件丢了就无法覆盖升级已装的包，只能卸载重装，请备份到工程之外的私密位置——仓库里没有副本。`verify-apk.sh` 最后会打印签名证书的 SHA-256，可用来核对是哪把钥匙。

**发新版本前**：把 `app/build.gradle.kts` 里的 `versionCode` 加一（当前是 3）。系统只允许 versionCode 更大的包覆盖旧版本。

可用环境变量：`ZCODE_REMOTE_KEEP_DAEMON=1`（Gradle daemon 留后台，加快重复构建）、`ZCODE_REMOTE_BUILD_TOOLS=<版本>`（verify-apk.sh 用指定的 build-tools）、`PORT` / `BIND`（serve-apk.sh 的端口和监听地址）。

构建输出里有一行 `Unable to strip the following libraries … libandroidx.graphics.path.so`，是本机没装 NDK 导致的，不影响使用。release 安装包不是逐字节可重现的：同样源码连建两次 SHA-256 不同，核对完整性以当次 `build.sh` 打印的哈希为准。

## 维护清单：ZCode 桌面升级后

每次 ZCode 桌面端升级后，跑一遍 `docs/remote-control-notes.md` 第 11 节的冒烟检查（下面是摘要，命令和当次结果以那份笔记为准）：

1. **新版本的手机页面在不在**：`curl -sI 'https://zcode.z.ai/remote/v4?app_version=<新版本>'` 是否 200。404 说明手机页还没发布，兜底版本先不要改成新版本。
2. **页面里 App 依赖的标记还在不在**：取回入口脚本，数 `data-mobile-page`（返回键）、`attachmentInputRef`（附件）、`createObjectURL`、`50*1024*1024`（保存副本）、`oauth/cli/init`（登录）等标记的出现次数，变成 0 的项要重新适配。
3. **电脑端生成的链接变没变**：打开远控弹窗用「复制链接」核对，还是 `https://zcode.z.ai/remote/v4` 加那四个参数、没有 `hash` 和 `t`。变了先更新技术笔记，再动代码。
4. **手机上走一遍**：真实链接登录、连接、发消息并打断、选附件、聊天页和首页的返回键、断网后重试、「保存副本」。
5. **收尾**：新旧版本目录哪个可用心里有数后，再决定要不要改兜底版本；把这轮的日期、版本、结果记下来，顺手更新技术笔记里版本相关的表格。

**兜底版本（免扫码入口用的 `app_version`）是编译期常量**：`app/src/main/kotlin/com/lululu/zcoderemote/web/EntrySelector.kt` 里的 `DEFAULT_FALLBACK_VERSION`，现为 `4.0.0`。内核留有改它的接口（`RemoteWebViewModel.setFallbackVersion`），但没有设置界面（见 `docs/ARCHITECTURE.md` 第 9.2、11 节），所以**改兜底版本 = 改常量重新打包发版**：改完常量，把 `app/build.gradle.kts` 里的 `versionCode` 加一，再跑 `bash scripts/build.sh release`。

改完代码后，按上一节的表跑 `check.sh`、`build.sh`、`verify-apk.sh`；要真机（含模拟器）整体过一遍就跑 `emulator-smoke.sh`。

## 已知限制

- **手机上不能新建或添加工作区**：手机页只支持访问桌面端当前窗口里已打开的工作区，切换用页面内的导航面板；要换到别的窗口的工作区，就在那个窗口再点一次远控入口。
- **WebView 里的登录流程和真机上的表现尚未在真机验证**：原生行为（文件选择、返回键、断网页等）只在模拟器（Android 15、WebView 124）上、用照 4.0.0 页面行为写的测试页验证过；真实页面只验证到登录页能加载出来。授权页会不会拒绝 WebView、附件和「保存副本」在真实页面上的端到端表现，都需要第一次真机使用时留意。
- 同一原因，**「保存副本」没有装进模拟器实跑**（协议逻辑有单元测试和 node 走查）；**真机扫码识别没有测过**（模拟器相机是测试图案）；「退出登录」的确认框弹出过、但没有真的按下去（它就是两行系统调用加确认框）；「读取剪贴板」按钮没有在模拟器上点过——模拟器放不进剪贴板文本，手动把链接粘贴进输入框的方式是实跑过的。
- 页面文字不跟随系统字号（钉在设计尺寸，可用双指缩放看小字）；App 和页面固定深色，不跟随系统外观。
